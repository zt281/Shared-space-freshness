# 本地 C++ 实验观察

2026-09-17，Linux，同机两个真实进程，POSIX 共享内存。普通 Debug 构建及 UBSan 构建的 CTest 均通过；UBSan 运行日志无 runtime error。

## 首轮快照实验的证据

| 行为 | 观察 |
| --- | --- |
| 未发布写入 | 发布者准备草稿时，读者仍读取原完整版本。 |
| 新鲜度边界 | 700ms 进入预警仍可用；1000ms 失效并拒绝产生新意图。 |
| 重传与心跳 | 接收时间或心跳次数改变，原业务证据时间不变，过期状态保持。 |
| 来源业务核验 | 核验证据更新可以使未变价格重新有效；仍等待已触发的恢复核对及稳定期。 |
| 缺口与未知时间 | 仅刷新证据不能修复缺口；未知/未来时间证据不会被当作新鲜数据。 |
| 主动停止 | 完整快照和技术恢复不解除主动停止。 |
| 指令时限与代次 | 当前数据新鲜仍不能执行过期意图或旧代次意图。 |
| 结果未知 | 模拟接口提交后保留未知，重复执行或另建覆盖指令被拒绝。 |
| 写入进程退出 | 发布者修改一个字段后在持锁状态真实退出；读者发现 owner death，将部分写入标为损坏，不作为业务可用数据消费。 |
| 新发布者恢复 | 新代次完整快照仅恢复数据；交易核对和稳定观察期完成后才能放行。 |
| 并发完整性 | 5000 次完整发布＋5000 次读取，记录校验一致、版本无倒退，最终版本为 5001。 |

共 25 项可执行行为检查通过。正常构建的全部 10075 条 JSONL 记录保存在 `evidence-local-linux/`；发布者和消费者 PID 可用于核对真实进程分离。

## 首轮结论与后续方向

这提供了“统一有效性视图可以封装同机跨进程发布与持锁退出”的首份执行证据。mutex、继承映射和单记录快照只是当前实验选择，不构成正式后端选型决议。

下一阶段仍需独立启动/挂接和跨节点传输候选、实际来源核验证据、逐笔事件机制、完整两腿/对冲账、真实时钟与持久化、逐级负载和目标部署验证。问题单继续保持 claimed。

## 后续：架构改良与有序双消费者（2026-09-17）

保留首轮原始证据，未覆盖旧文件。共享空间规则、消费者恢复与实验调度已分离；现有快照/恢复检查增加为 44 项，新增有序消费检查 38 项。普通 Debug 与 UBSan 全新构建均通过 CTest 两组共 82 项行为检查。

| 实验 | 观察 |
| --- | --- |
| 逐笔完整性 | 一个真实发布进程、两个真实消费进程，双方按序处理相同 24 条事件；逐条比对序号、版本与完整载荷一致。 |
| 慢组隔离 | 慢组进度保持 0，达到示例积压阈值 4 后受限，健康组持续逐条处理；记录模拟撤余与告警，撤余结果为 unknown，不假定成功。 |
| 超出共享缓冲 | 缓冲只有 8 条；慢组的前 16 条从完整本地记录补齐，最后 8 条从共享缓冲读取，没有静默跳进度。 |
| 恢复门槛 | 未补齐不能核对放行；补齐后仍需核对与稳定观察。主动停止保留，显式恢复不重发过期指令，结果未知的指令不重复提交。 |
| 必需记录缺失 | 有意截断新建实验日志；补读失败的整个批次不前进。故障扩展到该公共记录的两个依赖者，不能用最新快照掩盖缺失事件。 |
| 公共记录容量 | 注入记录数配额耗尽，下一条发布被拒绝，公开序号与快照不前进；两组限制新意图。不是实际磁盘写满验收。 |
| 消费者处理失败 | 仅落后组受限；失败事件不确认，重试相同序号，成功后不重复交付已确认事件。未保证外部副作用恰好一次。 |
| 连续正常更新 | 稳定观察期间正常新事件及时处理，不会重启稳定计时；再次失效/越过阈值仍会重新受限。 |

完整证据：[普通构建](evidence-ordered-linux/summary.json)、[UBSan](evidence-ordered-ubsan/summary.json)。每份包含 29 个 JSONL 文件、408 条原始记录及各场景本地实验日志。已逐条解析并核对两个消费者的完整载荷、序号、16 条补读与处理失败重试，不只检查摘要。记录包括 CPU/RSS 观察，但不作为容量达标依据。

实现及复现命令见 README。主工作区问题 29 保存本轮提交指针与进一步验证要求。

局限：这是单机继承映射、确定性调度的语义实验。缓冲和磁盘 I/O 共用锁，证明的是行为隔离，不是性能隔离；文件是本机二进制实验格式。消费进度不持久化；写日志/发布之间崩溃、实际磁盘故障、独立启动、跨节点及目标部署尚未验证。全部控制管道只负责实验安排和状态，不传业务事件；策略访问模型不暴露网络细节。

下一步优先验证进程独立启动、不同地址挂接与来源重新接管，检查当前依赖 fork 继承的便利条件被移除后，统一共享空间及恢复契约是否仍成立。生产存储选型、崩溃恢复、全量事件种类、完整对冲账和容量验证仍不能据本轮结题。

## 2026-09-19：独立启动、不同地址与发布者接管

用户确认只在旧发布者退出已被确认后自动接管；旧实例卡住或退出未知时保持受限。原型从用户提供的 GitHub 仓库恢复，基线提交精确为 `21720e9`。

新增具名 `Space`、独立启动进程入口及 69 项行为检查。普通 Debug 与 UBSan 的三组 CTest 全部通过：原有 44 + 38 项以及新增 69 项，共 151 项。完整观察、构建参数、源码快照、来源依据和可重跑审计见[本轮证据](evidence-independent-wsl/README.md)。

发布者与两个消费者实际使用不同映射地址；旧进程存活、SIGSTOP、关闭本地映射但尚未退出时均拒绝接管。正常退出或发布临界区外非正常退出后，新代次保留全局序号和完整日志；两个消费者分别处理全部 16 条事件，慢组含 5 条日志补读。过期/旧代次指令、未知结果、主动停止、核对和稳定期继续约束交易。

新的独立消费者要求启动核对；另修正新代次首次观察已有效时的 recovering 诊断，使其与已经关闭的交易门槛一致。原有两组基线启动假设保持不变。

本轮实现不是生产共享空间协议。进程退出前的发布操作已完整完成，不能证明写日志/发布中途崩溃可恢复；消费进度仍在内存。下一步应验证发布提交边界和消费恢复，而不是据此关闭整个架构问题或宣布跨节点/容量已通过。
