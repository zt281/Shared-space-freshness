## Question

## Answer

2026-09-10，经用户逐项确认，工作台的信息组织、核心操作与初始刷新目标已明确。结论用于后续布局/容量原型和前端架构设计；目前没有界面实现或性能实测结果。

### 工作区与面板目录

采用深色、紧凑的专业交易台，突出关键数字、当前操作对象和状态。目标使用环境至少为两块当前规格的 3440×1440 屏幕。统一提供按功能分类的面板目录，用户点击创建同类面板的多个实例，自行决定数量和摆放位置。采用以下首批面板类型，不把示例数量固化为布局或功能上限：

| 面板类型 | 核心用途 |
| --- | --- |
| 策略设置 | 查看和修改策略参数，展示提交与生效状态。 |
| T 形报价 | 查看某品种、期限的期权链，展示可配置列并编辑逐合约参数。 |
| 持仓监控 | 按所选账户、策略组或合约查看持仓。 |
| 策略监控 | 查看策略运行状态，对选定对象执行启停操作。 |
| 交易监控 | 查看订单与成交，撤销选定订单。 |
| 市场因子时序图 | 实时跟随、历史范围浏览及因子明细查看。 |
| 闪电下单 | 在价格梯上直接下单和撤单。 |
| 资金监控 | 查看所选交易账户的资金状态。 |
| 告警中心 | 展示告警，配合桌面通知和按级别配置的声音。 |

面板支持自由停靠、分栏、标签页和拆成独立窗口。工作区自动保存最近布局，同时支持命名保存多套布局；恢复面板、合约、列配置与联动组。显示器数量或布局变化时，将窗口恢复到可见区域并调整尺寸。工作区保存和恢复不自动提交参数草稿，也不自动重新启用闪电下单。

合约或品种期限只在用户选定的面板联动组内同步。账户和策略操作对象各自固定且始终可见，不能因合约联动隐式切换。面板、工作区与联动组的术语见 [业务术语](../../../CONTEXT.md)。

### T 形报价与参数编辑

行权价居中，左侧看涨期权、右侧看跌期权。每个面板面向一个品种与期限，列可配置，覆盖行情买卖价量、理论价与策略报价、隐含波动率、Greeks、持仓、挂单及逐合约参数。

支持表内编辑和多行批量修改，明确区分待提交草稿与后台实际生效值/版本。用户明确提交后，沿用 [策略运行与性能决议](04-strategy-performance.md) 中的完整参数版本校验与事件边界切换规则。多个面板可保留各自草稿；提交时检查基础版本，后台已有新版本时显示差异，待用户重新确认后提交，不静默覆盖。

品种/期限参数与逐合约参数的层级、共享关系、跨参数集批量提交的原子范围，以及生效回报契约，由 [期权定价、曲面拟合与参数状态](14-option-pricing-model.md) 进一步明确。

### 闪电下单与监控操作

闪电下单预先固定账户和数量；启用交易后，点击价格梯买卖侧直接提交订单，点击挂单发起撤单，不逐单弹窗确认。首次打开、切换合约或账户后先禁用下单，用户检查对象后显式启用。

价格梯平时自动跟随市价，鼠标进入下单区域时固定价格档位的视口位置，离开后恢复跟随；行情价量及订单状态继续更新。操作捕获点击时显示的合约、账户、方向、具体价格和数量，不根据随后变化的行号重新解释价格。

监控面板支持账户、策略组与合约筛选；策略监控启停选中对象，交易监控撤销选中订单。批量操作必须明确展示对象与范围并确认。停止策略、撤销挂单、紧急控制和订单归属的业务语义由 [订单、风控与恢复问题](07-order-risk-recovery.md) 决定，界面不能将它们混为同一状态。

当后台报告相关行情或交易状态失效，或前端连接中断时，保留最后数据并明显标注状态与时间，按受影响范围禁用下单、参数提交和策略启动。同步恢复后显式重新启用交易。撤单、停止等请求的可用性取决于对应连接，必须展示等待、已确认或结果未知等真实状态；前端关闭或断连本身不代表后台策略停止。

### 实时与历史因子图

首批代表性曲线包括不同计算窗口的实现波动率、MicroPrice 与加权中间价的差值、我方成交 theoEdge 与实际 Edge 的差值。它们的公式、单位、时间轴与成交参考时点尚未根据名称推定，另行确定数据口径。

支持跨月及更长历史的时间范围查询，先异步取得适合屏幕宽度的摘要，缩放后逐级细化，并可查询原始明细。浏览历史时保持选定范围，点击回到最新后恢复实时跟随。图表降采样不等于删除原始历史，也不能未经口径定义就用平均值替代尖峰或成交事件。

用户首选 DolphinDB 社区版作为存储候选，官方能力与资源边界见 [DolphinDB 调研决议](17-dolphindb-community.md)。长期保留周期、历史/实时切换、写入和查询预算，以及数据库部署方式仍需后续数据与架构问题确定。

### 展示与反馈验收目标

| 类别 | 已确认的初始目标 | 口径 |
| --- | --- | --- |
| T 形报价与价格梯 | 最多 20 次/秒 | 有新数据时按约 50 ms 节奏调度行情展示，可合并中间显示状态。 |
| 监控连续数值 | 10 次/秒 | 约 100 ms 调度节奏；关键业务状态变化按下述显示延迟单独验证。 |
| 因子图 | 5 次/秒 | 约 200 ms 实时展示节奏；不等于因子计算、采样或保存频率。 |
| 本地操作反馈 | p99 ≤ 50 ms | 从用户点击到出现本地可见反馈；发出请求后显示等待结果。 |
| 订单、成交、策略状态显示 | p99 ≤ 100 ms | 从状态到达前端接收入口，到受影响的可见面板显示更新。 |

前端状态显示计时包含接收后的解析、状态应用、跨窗口传递、排队和绘制；后台处理、交易通道及到达前端之前的网络时间另行观察。操作反馈不能提前冒充后台受理、挂单、撤单或策略生效结果。数据刷新节奏也不是整个窗口动画或输入响应的帧率上限。

行情中间展示状态可以合并，但不能丢弃重建盘口所需的数据；后台逐笔策略处理不受 UI 展示节奏影响。订单、成交与告警记录完整保留，视图及时更新，不以逐条闪现每个中间状态作为“完整”的定义。

以上均为待验证目标。多窗口原型需记录面板实例总数、可见数量、独立窗口数量、合约/行/列/曲线与数据点数量、输入率、突发负载、屏幕与缩放配置。逐级增加负载，报告实际刷新节奏、可见数据年龄、输入/状态延迟分布、队列积压、合并量与资源占用，明确哪些容量范围达到目标。历史查询、面板新建/关闭/隐藏/重开、布局恢复、断连恢复与参数编辑应同时进入场景；不能仅统计已完成更新而掩盖卡顿。
