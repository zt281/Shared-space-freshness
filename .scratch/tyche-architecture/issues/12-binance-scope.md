## Question

用户所说的股票相关交易，具体需要 Direct Stocks、bStocks、Alpha/Ondo 还是 TradFi 永续？首版 Binance 的现货、USDⓈ-M、COIN-M 和期权需要覆盖哪些，优先标的是什么？明确期权做市发生在哪个市场，以及相关账户是否具有所需产品和卖出开仓权限；公开产品存在不能代替账户能力验证。

以 [官方产品调研](../research/binance-products.md) 为事实输入。产品选择后，对所选产品仍未核实的 API 或模拟环境创建有界研究问题。

完成条件：明确首版必须覆盖、只预留和不覆盖的 Binance 产品；每类产品的代表性标的与交易用途；所依赖的账户、保证金及卖出开仓能力；未验证权限的处理边界。具体合约模型、订单状态与风控语义分别进入已有领域及交易状态问题，不在本项提前决定。

## Answer

2026-09-10，经产品访谈、所选产品的官方能力调查及用户对范围冲突的明确选择，本项已解决。Binance 首版聚焦 BTC/ETH 期权与 USDT 本位永续；股票借券卖空交给另选通道承接。

### 首版产品与用途

| 产品 | 标的范围 | 必要交易能力 |
| --- | --- | --- |
| Binance 加密期权 | BTC、ETH 的可交易期权合约，具体合约由产品目录发现并按策略配置选用 | 双边做市；必须能够在没有已有多头时卖出开仓。 |
| Binance USDT 本位永续 | BTCUSDT、ETHUSDT 永续 | 双边做市；订单与持仓模式按真实账户配置映射。 |

这些交易能力同时供既定的手工与自动交易路径使用；本项确定自动策略的双边做市需求，不以“能计算买卖两侧价格”代替真实下单能力。

BTC/ETH 加密现货、杠杆现货、币本位或其他本位合约、交割合约、其他加密标的、股票挂钩永续及 Alpha/Ondo 不列为 Binance 首版必需。它们将来是否接入另行扩展，不在本项自动加入实现范围。

### 股票业务的路径调整

用户原先要求 Direct Stocks 和 bStocks 均进行可借券卖空的双边做市。[股票产品研究](21-binance-stocks-market-making.md) 发现：bStocks 当前明确不支持借入，Direct Stocks 也没有已核实的普通账户借券卖空路径。用户据此选择暂缓 Binance 两类股票产品，保留股票借券卖空业务要求，另选接入通道。

股票合约目录仍需覆盖该通道和账户实际可交易的全部股票；活动合约由策略配置，不要求全目录同时做市。目录可交易、可借券和当前确有券源不能混为同一条件，下一项股票通道选择需分别验证。未来渠道对股票地域/标的覆盖、券源、费用、持仓和资金的具体限制需要与用户核对，不能默认所有美股随时可借。

### 账户范围、配置与资金操作

Binance 首版接入一个账户，采用普通账户交易路径。用户的真实模式仍待读取核对；组合保证金首版只做识别与扩展预留，不包含其实际交易路径。系统总体多账户目标不因 Binance 当前只接一个账户而取消。

配置记录预期模式，连接时核对交易所实际设置。不一致时明确说明差异并限制相关策略启动；账户或保证金模式变更必须由用户显式执行，不能为了启动某个策略自动切换整个账户的设置。普通/组合保证金、逐合约保证金设置、Futures 单向/双向持仓及 Options 卖出开仓模式必须分别表达；具体领域映射由 [跨市场合约、账户与资金模型](06-market-domain-model.md) 收敛。

首版由用户准备资金和资产，Tyche 查询并校验余额、可用资金/保证金及持仓状态。自动产品钱包划转、币种兑换和股票代币转换留到后续。普通 Options 与 Futures 的经济风险可以汇总查看，但不能据此把交易所不承认的跨产品保证金抵扣算成可用资金，事实依据见 [衍生品能力研究](22-binance-crypto-market-making.md)。

### 启用条件与未验证能力

| 项目 | 本项结论 |
| --- | --- |
| 产品开通与 API 交易资格 | 必须与目标账户及具体产品匹配；本轮未访问账户，不能标记为已验证。 |
| BTC/ETH 期权卖出开仓 | 用户要求的硬性能力。官方已向符合资格用户开放，但必须核对实际 Options 模式与 API 权限；仅能卖出已有多头或能力未知时，不启用该产品的实盘双边开仓策略。 |
| Options MMP、倒计时撤单 | 与普通卖出开仓能力分别记录，不能默认已有做市商专用权限。哪些策略必须依赖这些保护，由订单与风控决策明确。 |
| Futures 持仓/保证金模式与倒计时撤单 | 读取实际设置并按产品作用域校验；双边报价不自动要求切换成双向持仓。 |
| 余额、可用保证金、订单及持仓状态 | 按真实产品账户和资金范围核对，不将同一登录身份视为所有产品共享一个可用余额。 |
| 通道容量和配额 | 按官方定义的 UID、IP、产品及账户共享范围管理；活动集合与报价频率受实际额度和已验证容量约束。 |

对能力至少区分已验证可用、不可用、未验证。配置可以声明策略需要什么，不能制造交易所未授予的权限。所需卖出开仓能力缺失或未知时限制受影响产品；不能用其他产品的成功结果充当证明。

详细的拒单、未知结果、重连恢复、风险限制、策略停止及服务器端保护依赖，由 [订单、风控与恢复问题](07-order-risk-recovery.md) 继续确定。已选 [后台性能目标](04-strategy-performance.md) 保持不变；其适用负载须符合真实行情粒度、订单配额及原型验证范围，不能推广为外部交易所时延承诺。

### 接入验证与后续边界

[股票能力研究](21-binance-stocks-market-making.md) 和 [衍生品能力研究](22-binance-crypto-market-making.md) 已回答公开事实。实际账户准入、Options 模式/API 卖出开仓、服务器保护权限、限额和模拟环境均需在后续接入验证中分别留证据。本次没有配置凭据、签署产品协议、切换账户模式或执行真实交易。

官方 Options 当前公布的 demo 路由已记录在研究资产，但尚未实测合约、端点和开空能力；不自行猜测替代地址。模拟环境证明接口行为，生产账户验证证明实际准入，二者不能互相替代。

本决议新产生的独立问题是 [股票借券卖空的接入通道选择](23-stock-short-selling-access.md)；合约、账户和资金模型以及总体部署需消费该选择结果。该问题将按地图顺序单独认领并与用户讨论，不在本项替用户指定券商。
