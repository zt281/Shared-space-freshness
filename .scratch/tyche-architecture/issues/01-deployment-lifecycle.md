### 部署阶段与桌面隔离

- 测试和初版先在本地机器验证，桌面与 C++ 后台均支持 Ubuntu、Windows。此前选定的 Windows 性能参考机继续作为原基线，其他系统和部署位置分别验收。
- 后续国内 Linux 服务器连接 CTP，境外 Linux 服务器连接 Binance；QMT 实际接入继续延期。插件的具体进程/线程和节点分配由后端架构确定，不要求两节点采用不同策略拓扑。
- 一个桌面工作台连接两侧后台，分别展示账户、连接与数据状态。用户可从不同 Ubuntu/Windows 电脑访问，首版不要求同时操作；连接鉴权、旧客户端接管和工作区迁移方式由前端架构细化。
- 前后台生命周期分离。关闭桌面窗口或桌面网络断开不停止后台；桌面不承担节点间自动策略运行所必需的中转。前后台同机时整机休眠/关机会中断该机后台，不能把关闭窗口与关闭主机混为一谈。

### 核心共享空间契约

Tyche 是以统一共享空间接口连接插件的系统。跨市场与非跨市场策略保持相同的插件逻辑拓扑，通过不同的行情和指令对象连接交易路径；允许策略同时消费 CTP/Binance 行情并向两侧提交指令。

连续性指统一的逻辑空间，不要求跨机器相同原生指针地址或普通指针透明读写。插件通过统一接口、区域/偏移量或句柄获取有效数据视图；具体寻址和布局仍待设计。每份权威状态由一个指定模块写入，其他模块只读或提交变更请求；不同状态可有不同写者。

写者完成一份记录后显式发布完整版本，读者不应读到半次更新。这不承诺多个对象原子更新、所有节点同时可见或任意内存写入自动一致。发布单元、顺序、保留与回收、指令去重、写者所有权及恢复代次由后端架构细化。

首版同机共享内存、跨机支持普通网络传输；传输实现可替换，RDMA 是未来可选加速而非必要部署条件。零拷贝需按插件读写、传输缓冲区及接收视图等实际路径验证，不承诺跨境端到端零拷贝。接口一致不代表各部署位置具有相同延迟；跨境通信须计入相关策略完整链路测量。

### 故障限制、急停与自动恢复

- 普通模块下线时，使相关依赖功能受限，其他节点和无关功能继续运行；单节点故障不应使另一节点进程崩溃。
- 持仓、风控等关键模块失效时，对其所有直接/间接依赖交易路径急停，包括跨节点依赖；无依赖的策略继续运行。关键模块完整名单、有效性和检测期限待后续明确，不承诺瞬时发现失联。
- 急停停止相关路径产生新订单；订单通道仍有效时尝试撤销相关已有挂单，结果以回报/查询确认。保留后台用于重连和核对，不自动市价平仓；通道失联不能视为已撤单。
- 重连/重启后自动重新加入共享空间。依赖重新有效、共享数据版本及重启代次核对完成、外部订单和持仓核对完成后，自动恢复策略。只有索引追平不足以启动；任一门槛未满足时继续受限，不要求正常恢复流程由用户手动启动。
- 上述自动恢复针对故障恢复，不将用户主动停止的策略自动改为运行。主动启停状态的持久化和恢复规则由订单/恢复问题定义。
