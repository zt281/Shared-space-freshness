## Answer

本问题通过上述访谈解决验证范围与运行门槛。以下为设计要求，不表示已有程序、测试通过记录或交易权限。

### 首版能力与证明范围

| 能力 | 已确认要求与证明边界 |
| --- | --- |
| 本地确定性重放 | 覆盖指定策略组的完整决策链，比较报价、报撤单意图、风控及持仓变化；不承诺复现操作系统调度，也不以加速重放证明实际延迟。 |
| 接口仿真 | 可编排订单回报及故障，用于验证状态、风险和恢复；仿真成交不用于证明真实成交概率或预测收益。 |
| 模拟柜台联调 | 验证目标通道支持范围内的接口行为；按通道/产品分别记录通过、失败与未覆盖，不能替代实际账户能力证据。 |
| 完整历史回测 | 保留后续阶段。首版预留输入、时钟和订单通道接口；未来先验证单个期货合约的撮合、延迟与账本，再扩展期权链及对冲。 |

早期 OpenCTP 回放安排沿用[已确认阶段安排](13-qmt-language-boundary.md#answer)，不直接等同上述全部能力已通过。

### 重放输入与一致性

- 保存指定策略组的行情、订单成交、参数生效、启停、依赖状态和逻辑时间事件，以及初始持仓、资金、挂单和必要模型状态；固定实际消费顺序及所用共享输入版本。
- 外部共享拟合等结果可作为记录输入；模型自身重算须另声明验证范围，不因策略消费重放通过而视作模型重算通过。
- 验证与实际运行共用 C++ 策略、定价、订单状态和风控逻辑，环境替换输入、时钟及通道。固定代码、初始状态、事件顺序及必要随机种子。
- 同一受支持构建/运行环境下，报撤单意图、离散状态、数量和可执行价格应一致。跨环境浮点比较允许预先声明且有业务依据的容差，但不得掩盖交易行为差异；报告保存首次差异位置、输入版本及比较规则。

### 必过异常与变更重验

首版必过场景包括重复/乱序回报、部分成交与撤单交错、提交后结果未知、断线重连、进程重启、关键依赖失效和执行证据写入失败。预期行为沿用[订单风控与恢复决议](07-order-risk-recovery.md#answer)，验证不重复发单、未知风险占用保留及不错误恢复等契约。

策略、定价、风控或接入行为变更，以及新增通道/产品，重验受影响范围。日常参数在明确验证过的参数组合、容量和风险范围内调整，只需运行时校验及版本留痕；超出范围先验证。各参数分别在界内不能证明其组合已经覆盖。

### 真实发单与环境隔离

- 后台检查适用的验证通过记录，再由用户显式启用真实发单；记录覆盖策略代码、相关配置和目标通道/产品范围。该门槛不替代既有运行时风控和恢复条件。
- 回放和仿真使用独立环境身份、账户映射及状态空间，不加载真实交易凭据或真实发单路由；模拟柜台显式配置模拟端点。
- 验证结果不写回实盘持仓、订单或运行状态。重放结束不切换为实盘；真实运行另行启动并核对当前账户状态。
- 缺少必需证据的范围不得开放正常真实交易。保留后续由用户单独授权的受限实盘验收，绑定账户、合约、时段和订单/仓位上限，保留既有风控，用于补足证据；通过后另行启用正常交易。本次仅决定该路径存在，不授权执行验收。
